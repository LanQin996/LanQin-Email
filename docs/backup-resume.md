# 加密备份上传：分片、检查点与继续任务

管理端新执行的上传任务已默认使用加密检查点；独立 CLI 可显式启用。它们仍上传同一份经过可信 SHA-256 预检的 age 密文，不重新采集邮件、不持有恢复私钥。恢复归档格式和对象名不变。

| 后端 | 继续能力 | 完成判断 |
| --- | --- | --- |
| S3 / S3-compatible | 原生 multipart，16 MiB/片；重新查询原 upload ID 的部件，跳过已确认且与本地固定来源一致的部件 | 条件完成 `If-None-Match: *` 后核对归属元数据、准确大小及完整密文 SHA-256 回读 |
| Google Drive | 预分配 file ID、持久化 resumable session，16 MiB 分块；用服务端 `308/Range` 查询实际偏移 | 原 file ID、目录、地点/来源属性、大小、MD5 和完整密文 SHA-256 回读一致 |
| 标准 WebDAV | 没有通用的按字节追加协议；固定对象名、独占完整 PUT，继续时核对丢失的完整成功响应 | 已存在对象完整回读匹配原可信摘要后确认成功；部分/冲突对象拒绝覆盖 |

这些能力已通过隔离 TLS 协议及实际子进程终止测试；真实 AWS/R2/B2/WebDAV/Google 云账号尚未验收。不要把“分块协议单测通过”写成供应商联调或完整灾备验收通过。

## 管理端操作

失败、部分成功或中断的上传/快照任务，具备已发布归档记录和检查点进度时可显示「继续上传」；服务端在入队和执行前再检查实际归档、检查点和地点是否可用。仅真实超级管理员可以操作。继续前检查地点配置 revision 和原配置指纹；归档 ID、摘要、大小及地点身份保持原样，不能借继续操作更换上传目标或密钥。

- 原任务重新入同一个有界队列，使用新的租约/fencing token；每任务最多显式继续 10 次，保留继续时间、发起管理员 ID、上次状态和错误码。重复 HTTP 请求不会追加第二份队列工作。
- 已成功地点的结果保留且不再次上传；只继续未确认成功的地点。较旧任务继续完成，不会替换较新逻辑任务的最近成功记录；继续操作跳过全部自动保留清理，避免旧归档的迟到确认时间被当作清理新数据的依据，后续正常新备份再执行保留策略。
- 快照任务使用已经生成的同一归档，不重新进入在线采集。尚未成功生成归档、旧版本没有检查点的任务，以及明确取消的任务不支持继续；可另行发布/创建新任务，但那是新的上传操作。
- 重启仍会把过期任务标为中断，不自动重放网络操作。管理员明确继续后，新进程加载检查点、重新核对原密文和远端进度，再执行后续步骤。
- 界面只显示已确认字节数、总大小、回读状态、继续次数及安全错误码；会话 URL、multipart upload ID、私有绑定摘要和 worker token 不出现在 API/下载报告/日志中。等待或传输中不会把旧失败结果误显示为当前失败。
- 改名或修改保留策略不改变凭据指纹；配置 revision 变化仍要求刷新后重试。Drive 正常短期 token 刷新可继续，但重新授权到新账户/目录会拒绝旧任务。

## 持久化与互斥

应用使用既有 `system_settings` 存储 `backup.transfer.v1.<job>.<destination>`：每地点一个 AES-GCM 认证加密记录，AAD 绑定完整用途/key。会话、部件清单及绑定状态均加密，API 只复制安全进度 DTO。检查点、对应任务进度和当前租约 CAS 在同一短事务内提交；文件哈希和网络不持有业务数据库连接。

已记录过的检查点丢失、篡改、换钥或来源不匹配时停止，不把它静默当成首次上传。归档导出的私有 SQLite 副本和维护安装副本均排除这些运行态记录，避免恢复旧上传会话或把它们当作可自动重放的工作。

API 多实例继续还要求各实例能读取同一认证归档目录，并使用相同配置主密钥；检查点不会自动复制每台机器上的本地密文。缺失归档时停止，不换一份新快照冒充原任务。多实例租约依赖部署时钟正常同步。

管理端会话接口为 `POST /api/admin/backups/jobs/{id}/resume`，body 为 `{"destinationsRevision":"<current-revision>"}`，成功返回同一任务的 `202`。任务 DTO 新增 `canResume`、`resumeCount`、`resumeAudit` 和逐地点 `transfers`（phase/已确认 bytes/total/清理安全错误码）；这些不是可由客户端指定的会话或本地路径。

单个管理端归档仍上限 1 GiB，CLI 仍上限 5 GiB。每地点最多三次有界尝试，原任务一小时时限、每尝试默认二十分钟、两个并发地点和队列上限继续生效。S3 列部件、Drive 查询/块数量和响应体都有上限；无进度、越界/回退 Range、错误 ID/目录或最终内容不符均拒绝。

## 独立 CLI 检查点

配置文件继续只包含凭据**环境变量引用**；在受保护环境中提供 `LANQIN_BACKUP_SECRET_KEY`（Base64 的 32 字节随机密钥），并准备独立私有目录：

```text
./lanqin-backup upload --config /secure/destinations.json --in /backups/example.age --expected-sha256 <trusted-64-hex> --resume-dir /private/upload-checkpoints --resume-id migration-20261031-01
```

中断后，用同样的目录、operation ID、主密钥、同一密文和未变更的地点配置重跑。`--resume-dir` 与 `--resume-id` 必须成对；ID 为 1..64 个字母、数字、`_` 或 `-`。一个 operation 最多 64 个地点。更改密文或凭据会使已有绑定失败，不会把旧会话拿去发送不同数据。

检查点文件与 namespace 索引使用 AES-256-GCM、随机 nonce 和独立 HKDF 用途密钥；索引先于新的目标状态落盘。已知目标状态文件或已有 namespace 索引缺失时停止。Linux 使用 `flock`，Windows 使用 `LockFileEx`，同一 operation 在整个进程执行期间独占锁，进程终止由操作系统释放，不凭文件年龄抢锁。Linux 原子 rename 后目录 fsync；Windows 使用替换及 write-through 的 `MoveFileEx`。文件都在显式私有根内，拒绝链接/路径逃逸，错误不回显敏感内容。

Linux 目录必须由当前操作者所有且无组/其他用户权限；Windows 要另行设置私有 ACL，Unix `0600/0700` 不能替代 DACL。不要删除锁/索引/状态文件来强制继续，或将同一 operation 指向丢失全部历史的新目录；没有独立历史时无法证明此前远端结果。检查点没有自动保留清理，进程被强制终止还可能留下本次私有密文 spool，应核对容量和归属后处理。

CLI 不加检查点参数时保留旧的完整 PUT 行为。CLI 信号中止保留检查点以便人工继续；它不自动对未知远端内容执行删除。主密钥不是 age 恢复私钥，也不是 AWS 或 Drive 的凭据，不能把这些值放入 `--resume-id` 或命令行参数。

## 存储端权限与失败边界

- S3 检查点模式需要 multipart 创建/部件上传/部件查询/完成、对象读取及取消时 abort。AWS IAM 通常对应 `s3:PutObject`、`s3:ListMultipartUploadParts`、`s3:GetObject`、`s3:AbortMultipartUpload`；不要求列整个桶，也不请求删除完成对象。兼容服务必须正确支持条件完成和相关协议；缺少权限/能力时明确失败，不降级为覆盖式上传。
- S3 在创建会话后、收到/持久化 upload ID 前进程或网络中断，可能无法确认该会话。此时只探测已知对象并报告 `upload_session_uncertain`，不猜测 upload ID、不遍历其他上传、不静默创建第二个会话。需存储端生命周期清理或操作者核对后开启新任务。
- S3 完成请求的响应丢失时，先读取同一对象核对元数据和实际 SHA-256；已完成者不再次发布。完成状态仍不确定时保留原会话，不自动换新对象名。
- Drive 先保存预分配 file ID，创建/过期会话重试仍指向同一文件 ID。上传中若能看到属于该任务的零字节占位元数据，不误报成功或以文件 PATCH 覆盖，仍查询原 session；最终必须验证完整文件。未知 origin/path、无效 Range、错误 ID/父目录/摘要及虚假的成功响应均拒绝。
- WebDAV 已有部分对象不等于可继续的完整备份。若完整 GET 与可信收据不符，不重发覆盖、不删除该对象；应核对后处理或明确创建新任务。没有标准追加协议，就不声称已实现 WebDAV 的字节偏移续传。
- 只上传到原配置对应的 HTTPS origins，保留证书、DNS/IP 固定、无代理环境和拒绝重定向保护。没有加入允许私网 NAS 的开关；显式内网白名单及对应验收仍待后续实现。

## 明确取消与分片清理

管理员明确取消运行中的管理端任务时，先中止传输，再在原租约下用最多十秒的独立清理上下文尝试关闭**已知 S3 未完成 multipart session**。请求为带原 upload ID 的 `AbortMultipartUpload`，不会调用完成对象的 DeleteObject；已经确认成功的副本保留。404 仅说明该会话已不存在，不证明某个完成对象已被删除。

服务器退出/租约丢失时保留会话以便继续。已完成的检查点、变更/停用的地点、不明确的会话、Drive/WebDAV 非标准临时内容都不会被猜测删除。清理失败在地点进度中显示，不能把取消当作撤销远端已经接受的所有内容；未能在时限内关闭的会话、已失败任务残留和未知创建结果仍需云端生命周期或人工核对。
